# Проверки очереди регистрации

`registration_queue.bsl` — модуль объекта временной внешней обработки для тестовой
базы с текущей demo-конфигурацией. Вызовите `ВыполнитьПроверки()` на сервере вне
транзакции. На время запуска остановите регламентную обработку и доставку сообщений.
Тест создает собственные узлы, склады, товары и проведенные заказы, вызывает реальные
обработчики и запись заказа. Все изменения откатываются транзакцией теста.

Проверяются обязательный реестр, пустой реестр без возврата к глобальным настройкам,
пустая очередь, связанная регистрация заказа и товара, ограничение выбранным планом
и узлом, выбор обработчиков исходного и связанного объекта, пустой выбор сценариев,
несколько сценариев с общей очередью, очистка временных таблиц, сохранение результатов
и автоматическая регистрация из события записи заказа. Пакетная проверка использует
два заказа с разными узлами, отдельные и общий товары, повторяющиеся строки товара:
проверяются точные пары товар/узел, отсутствие лишних маршрутов, состав связанных
заданий и число исходящих сообщений. Заказ без маршрутов не создает связанных заданий.

Дополнительно проверьте форму `КОД_РучнаяРегистрация`:

1. Выберите в плане обмена с сайтом проведенный заказ с товаром. Запустите полную
   цепочку: в исходящей очереди должны появиться сообщения обоих типов. В подробной
   расшифровке сверху выводится таблица «Исходные объекты» с заказом, снизу — таблица
   «Связанные объекты» с товаром. Обе содержат ссылку, план обмена и узлы; ссылки
   открываются через расшифровку ячеек.
2. Снимите обработчик связанной регистрации: повторный запуск добавляет только заказ;
   нижняя таблица не выводится. После предыдущего запуска в ней не остается старых строк.
3. Снимите все конвейеры или все обработчики: новые сообщения не появляются,
   исходные ссылки остаются в верхней таблице с пустыми маршрутами.
4. Оставьте только фильтр: запуск завершается с пустой расшифровкой маршрутов.
5. Отметьте также строки другого плана в дереве: запуск из выбранной строки
   продолжает использовать только ее план и конвейеры.
6. Выберите два заказа с общим товаром, повторите товар в строках заказа и исходную
   ссылку в списке. Настройте разные узлы заказов: отдельные товары должны получить
   только узлы своего заказа, общий — объединение узлов обоих заказов. В отчете нет
   повторов ссылок и узлов; общий товар выводится один раз.
7. В кратком режиме исходные объекты считаются отдельно от связанных: для двух
   зарегистрированных заказов с одним общим товаром — «исходных объектов: 2 из 2;
   связанных объектов: 1». Число узлов учитывает уникальные узлы обеих групп.
8. Если связанный объект уже присутствует среди исходных ссылок, он остается только
   в верхней таблице. При отсутствии маршрута у связанного объекта он не попадает
   в нижнюю таблицу: расшифровка использует результаты маршрутизации конвейеров.

# Проверки регистрации с учетом отправителя

`sender_registration.bsl` — модуль объекта временной внешней обработки для тестовой базы с установленной demo-конфигурацией. Создайте внешнюю обработку в Конфигураторе, перенесите модуль и вызовите экспортную процедуру `ВыполнитьПроверки()` на сервере. Для запуска нужен доступ к менеджерам объектов расширения и запросам.

Проверки вызывают реальные методы ядра и новый обработчик, используют типизированные ссылки и временные таблицы; объекты базы и исходящая очередь не записываются. Проверяется чтение отправителя из дополнительных свойств товара вне состава плана обмена и отсутствие отправителя после удаления свойства. Проверяются приоритеты явного решения и настройки сценария, отсутствие отправителя, удаление единственного маршрута, повторный запуск, сохранение дополнительных колонок, неверный порядок этапов, снимок параметров задания, отсутствие неявного наследования.

Дополнительно в тестовой базе задайте перед записью заказа дополнительные свойства
`КОД_Отправитель` и `КОД_ОтправлятьОбратноОтправителю = Ложь`: в исходящей очереди
не должно быть нового сообщения для отправителя. При значении `Истина` применяются
обычные правила маршрутизации. Без отправителя ручная и автоматическая регистрация
сохраняют обычный состав получателей. Связанные товары получают только узлы заказов,
оставшиеся после исключения отправителя.

Статическая проверка XML не заменяет выполнение этих проверок на платформе 1С.
